# SSH 主机排查

> 平台执行约定：只读工具直接调用；`ssh.exec` 是变更工具，会返回 `awaiting_approval`，说明平台已挂起等审批，不要重复提交同一条命令，也不要调用 `task.*`、`approval.*`。审批被拒绝或命令失败时如实说明，不要绕过审批。只使用当前任务工具清单里的工具，不要直接连上游 MCP。

目标：容器、K8s 和日志证据不足时，登主机确认系统层状态。只做只读、有界、可复核的检查。

## 前提

- 先用 `asset.get` 确认资产存在，并看清环境、负责人、SSH 用户、跳板机（`sshJumpAsset`）和 `sshHostKeyFingerprint`。
- 没有信任指纹时 `ssh.test` / `ssh.exec` 会被拒绝。让管理员在资产页「校验主机密钥」并确认指纹，不要尝试绕过校验。
- `ssh.test` 只验证连通和主机密钥，不执行命令；连通确认通过后再考虑 `ssh.exec`。
- 不连生产主机做测试；只对用户明确指定的资产执行。环境等级不清楚时先查资产或问清楚，不要默认。

## 命令规范

- `ssh.exec` 即使命令只读也进入审批。一次提交一条命令，等审批结果，不要重复调用或并行试探。
- 命令必须非交互、无 TTY、无分页，输出有界：加 `head` / `tail` / `-n` 限制行数，单次执行控制在超时时间内。
- 只读检查示例：
  - 负载与内存：`uptime`、`free -m`、`vmstat 1 3`
  - 磁盘：`df -h`、`df -i`、`lsblk`
  - 进程：`ps -eo pid,ppid,%cpu,%mem,etime,comm --sort=-%cpu | head -15`
  - 内核与系统日志：`dmesg -T | tail -100`、`journalctl -p err -n 100 --no-pager`、`systemctl --failed --no-pager`、`systemctl status <unit> --no-pager`
  - 网络：`ss -s`、`ss -lntp`、`ip -br addr`、`ip route`
- 禁止：交互式命令、`sudo` 修改系统、重启或停止服务、`kill`、`rm`/`mv`、改配置、写文件、重定向保存输出、`curl` 外部地址、读取私钥/凭据/token/环境文件。
- 输出里有敏感信息时先脱敏再写进结论；输出被截断时说明截断位置，不要当成完整结果。
- 跳板机由平台按 `sshJumpAsset` 自动转发，不要在命令里手工再跳。

## 结论要求

- 给出资产名、环境、执行的命令、关键输出和采集时间，按负载、内存、磁盘/inode、进程、内核日志、网络归类。
- 只报告实际输出；审批被拒绝、连接失败或命令超时要如实说明，不假装已经执行。
- 主机侧结论要说明是否足以解释上游现象；证据不足时写清还需要看什么。
