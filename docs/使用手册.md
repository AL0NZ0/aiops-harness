# AIOps Harness 使用手册

对应版本：0.1.0。平台做扩展层：知识库、运维工具、任务 API、只读放行和变更审批。主力推理和会话仍由 DeepSeek Harness（DSH）、WorkBuddy 等外部 Agent 负责；平台自己的任务执行器是可选的轻量模型循环。

## 1. 它是什么，不是什么

- 是：一个可独立运行的运维任务平台，带身份、任务、事件、审计和审批；配置模型后平台自己能做有限步排查，没有模型时按 `playbook.json` 跑知识检索。
- 是：DSH / WorkBuddy 的工具后端。外部 Agent 通过 `/api/v1` 或 MCP 代理调用平台工具，变更仍然走平台审批。
- 不是：通用 Agent 框架。平台模型循环最多 8 轮，只做临时运维任务；会话、长期记忆和复杂编排仍由 DSH / WorkBuddy 负责。
- 是：任务、事件、审批、审计持久化到 MySQL 8，重启不丢；审批消费是数据库条件更新，保证只执行一次。测试和本地无数据库时用内存实现。

## 2. 启动

日常运行用 Docker（见 9.1），下面是从源码开发/调试的方式。要求 Node.js 22 及以上。

```sh
npm install
docker compose up -d mysql    # 只启动本地 MySQL 8.4，映射 127.0.0.1:3307
npm test                      # 带 .env 时 MySQL 集成测试会实跑，否则跳过
npm start
```

默认监听 `127.0.0.1:8787`，浏览器打开就是控制台。数据库连接从 `.env` 读取（权限 0600，不要提交）：`AIOPS_DB_HOST`、`AIOPS_DB_PORT`、`AIOPS_DB_USER`、`AIOPS_DB_PASSWORD`、`AIOPS_DB_NAME`。`docker-compose.yml` 会读同一份 `.env` 里的 `MYSQL_*` 变量。表在启动时自动创建并做增量迁移（任务、事件、审批、审计、用户、会话、API key、安全事件、登录失败计数、`schema_migrations`）。

可用环境变量覆盖：

| 变量 | 作用 |
| --- | --- |
| `AIOPS_CONFIG` | 配置文件路径，默认 `config/platform.json` |
| `AIOPS_HOST` | 监听地址，默认取配置里的 `host` |
| `AIOPS_PORT` | 监听端口，默认取配置里的 `port` |
| `AIOPS_DB_HOST` / `AIOPS_DB_PORT` | MySQL 地址，默认 `127.0.0.1:3306` |
| `AIOPS_DB_USER` / `AIOPS_DB_PASSWORD` / `AIOPS_DB_NAME` | MySQL 账号和库名 |
| `AIOPS_DB_CONNECT_TIMEOUT_MS` / `AIOPS_DB_RETRY_MS` | 启动时等待 MySQL 的总时长（默认 60000）和重试间隔（默认 1000） |
| `AIOPS_MODEL_BASE_URL` | OpenAI 兼容模型端点，例如 `https://api.deepseek.com/v1`；只在没有启用的模型 provider 时作为兜底 |
| `AIOPS_MODEL_NAME` | 兜底模型名，例如 `deepseek-chat` |
| `AIOPS_MODEL_API_KEY` | 兜底模型端点密钥；只放环境变量，不要写进 `config/*.json` |
| `AIOPS_MODEL_API_KEY_ENV` | 兜底配置从哪个环境变量读密钥，默认 `AIOPS_MODEL_API_KEY` |
| `AIOPS_MODEL_PROVIDERS_FILE` | 模型 provider 数据文件，默认 `data/model-providers.json` |
| `AIOPS_NOTIFICATIONS_FILE` | 通知 webhook 数据文件，默认 `data/notifications.json` |
| `AIOPS_ALERT_SOURCES_FILE` | 告警接入源数据文件，默认 `data/alert-sources.json` |
| `AIOPS_ALERT_MAX_CONCURRENCY` | 同时运行的告警排查任务上限，默认 3，范围 1-50；超限的告警直接返回 `capacity` |
| `AIOPS_PUBLIC_URL` | 通知里审批深链和告警源地址的基地址，默认 `http://127.0.0.1:<端口>`；内网 HTTP 写 `http://<IP或域名>:<端口>`，启用 TLS 写 `https://...` |
| `AIOPS_INTERNAL_TOKEN` | 覆盖配置文件里的 `internalToken`；K8s 从 Secret 注入，header 模式和内部工具调用使用 |
| `AIOPS_TRUST_PROXY` | 设为 `1` 时从 `X-Forwarded-For` 最右侧取客户端 IP；只适用于平台不能绕过反向代理直接访问的拓扑。默认只信 TCP 对端，防止伪造 XFF 绕过登录限流 |
| `AIOPS_TLS_CERT_FILE` / `AIOPS_TLS_KEY_FILE` | 同时设置后平台以 HTTPS 启动（PEM 证书链和私钥），自动给会话 Cookie 加 Secure；只设一个直接拒绝启动。K8s 默认由 Ingress 终结 TLS，不要设；平台直连 HTTPS 时要同步改 probe 和 HEALTHCHECK |
| `AIOPS_INSTANCE_ID` | 多实例部署时每个副本的唯一标识（K8s 可用 `POD_NAME`）；启动回收只处理本实例 runner 的任务。不设置时保持单实例行为 |
| `AIOPS_APPROVAL_POLL_MS` | 审批等待轮询存储的间隔，默认 2000 毫秒；审批在其它副本通过后最迟这么久被 runner 看到 |
| `AIOPS_ALLOW_ADMIN_SELF_APPROVAL` | 设为 `1` 时允许 admin 审批自己发起的变更；默认关闭。approver/operator 在任何情况下都不能自批；开启后网页审批会二次确认，事件带 `selfApproved` 标记 |
| `AIOPS_API_KEY_RETENTION_DAYS` | 过期/吊销的 API key 记录保留天数，默认 30；0 关闭 |
| `AIOPS_API_KEY_REMIND_DAYS` | API key 到期前多少天发通知，默认 7；0 关闭 |
| `AIOPS_METRICS_TOKEN` | 设置后 `/metrics` 要求 `Authorization: Bearer <token>`；不设置则匿名可抓，只适合本机。对外或共享网络必须设置 |
| `AIOPS_LOG_REQUESTS` | 设为 `1` 时每个 HTTP 请求输出一条结构化访问日志 |
| `AIOPS_MODEL_TIMEOUT_MS` | 单次模型请求超时，默认 120000 毫秒 |
| `AIOPS_MODEL_MAX_STEPS` | 平台任务最多几轮工具调用，默认 8，范围 1-30 |
| `AIOPS_MODEL_MAX_TOKENS` | 单次模型响应 max_tokens，默认 4096 |
| `AIOPS_MODEL_TEMPERATURE` | 采样温度，默认 0.2 |
| `AIOPS_MODEL_TOOL_OUTPUT_CHARS` | 单个工具结果回填给模型的上限，默认 12000 字符 |
| `AIOPS_MODEL_STREAM` | 兜底模型是否流式输出，默认开启；设为 `0` 关闭 |
| `AIOPS_MODEL_MAX_RETRIES` | 兜底模型可重试错误的最大重试次数，默认 2 |
| `AIOPS_MODEL_RETRY_BACKOFF_MS` | 首次重试等待毫秒数，之后指数退避，默认 500 |
| `AIOPS_MODEL_INPUT_COST_PER_1M` / `AIOPS_MODEL_OUTPUT_COST_PER_1M` | 兜底模型的输入/输出单价（每百万 token），两者都设置才估算成本 |
| `AIOPS_MODEL_CURRENCY` | 成本货币单位，默认 `USD` |
| `AIOPS_MODEL_DISABLE` | 设为 `1` 强制关闭平台模型执行，即使配置了端点 |
| `AIOPS_RATE_LIMIT_WINDOW_MS` | 限流固定窗口，默认 60000 毫秒 |
| `AIOPS_RATE_LIMIT_MAX` | 每个客户端 IP 每个窗口的 API/MCP 请求上限，默认 1200；0 关闭 |
| `AIOPS_RATE_LIMIT_WRITE_MAX` | 每个账号每个窗口的写请求上限，默认 60；0 关闭 |
| `AIOPS_RATE_LIMIT_LOGIN_MAX` | 每个客户端 IP 每个窗口的登录尝试上限，默认 15；0 关闭 |
| `AIOPS_RATE_LIMIT_DISABLED` | 设为 `1` 完全关闭通用限流 |

Docker 镜像会把 `AIOPS_HOST` 设为 `0.0.0.0`。如果要用真实凭据，建议改回 `127.0.0.1` 或放在有认证的反向代理后面。

## 3. 身份和权限

平台有两种模式，由 `AIOPS_AUTH` 决定：

- **默认：本机 header 模式**。身份来自请求头 `x-actor-id`，不是登录体系。任何能访问服务的人都能自己填这个头，只能在本机可信环境使用。
- **`AIOPS_AUTH=local`：账号模式**。用户名 + 密码登录，服务端会话（HttpOnly Cookie + CSRF），角色和 API key 存在 MySQL；页面入口是 `/login`。DSH 代理用 `AIOPS_API_TOKEN`（API key）访问，不再使用 header。

首次以账号模式启动且用户表为空时，用 `AIOPS_ADMIN_USERNAME`（默认 `admin`）和 `AIOPS_ADMIN_PASSWORD` 创建管理员，角色是 `admin + operator + approver`，并要求首次登录后改密。**必须在首次启动前设置密码**，否则平台只打印警告、没有可用账号。

| 角色 | 能力 |
| --- | --- |
| `operator` | 提交任务、执行只读工具、取消自己的任务；只看自己发起的任务和审批；适合只配 API key 的客户端账号 |
| `approver` | 提交任务、执行工具、审批别人名下的变更、取消未结束任务；看自己发起的任务和有审批记录的任务；必须设置登录密码 |
| `auditor` | 全局只读：看所有任务、事件、审计和审批记录；不能提交任务、执行工具或审批；必须设置登录密码 |
| `viewer` | 只看自己发起的任务；不能提交任务，不能执行工具；适合只配 API key 的客户端账号 |
| `admin` | 全部权限；用户管理、API key 管理；不能审批自己名下的变更；必须设置登录密码 |

相关环境变量：

```sh
AIOPS_AUTH=local                 # 启用账号模式；不设置则保持 header 模式
AIOPS_ADMIN_USERNAME=admin       # 空库 bootstrap 管理员用户名
AIOPS_ADMIN_PASSWORD=...         # 空库 bootstrap 管理员密码（至少 12 位）
AIOPS_INTERNAL_TOKEN=...         # 可选：覆盖 config 的 internalToken；K8s 从 Secret 注入
AIOPS_SESSION_IDLE_MS=43200000   # 空闲会话过期，默认 12 小时
AIOPS_SESSION_ABSOLUTE_MS=604800000  # 会话绝对过期，默认 7 天
AIOPS_LOGIN_MAX_FAILURES=5       # 同 IP + 用户名连续失败次数，默认 5 次
AIOPS_COOKIE_SECURE=1            # HTTPS 部署时加 Secure；内网 HTTP 必须为 0/不设置
AIOPS_ALLOW_ACTOR_HEADER=1       # 账号模式下额外允许 x-actor-id（仅本机调试）
AIOPS_APPROVAL_TTL_MS=86400000   # 挂起审批存活时间，默认 24 小时；0 关闭
AIOPS_ALLOW_ADMIN_SELF_APPROVAL=0  # 默认 0；设为 1 才允许 admin 审批自己发起的变更
AIOPS_TASK_RETENTION_DAYS=30     # 终态任务及事件/审计/审批保留天数，默认 30；0 关闭
AIOPS_EVENT_RETENTION_DAYS=90    # 安全事件保留天数，默认 90；0 关闭
AIOPS_SECRET_KEY=...             # 数据加密密钥，32 字节 base64 或 64 位 hex；不设置则用密钥文件
AIOPS_SECRET_KEY_FILE=data/secret.key  # 密钥文件，默认 data/secret.key，缺失时自动生成 0600
AIOPS_API_KEY_TTL_DAYS=90        # 未填过期时间时 API key 的默认有效期；0/不设置表示不自动过期
```

### 平台任务执行器（可选）

不配置模型时，网页和 `POST /api/tasks` 仍然按技能目录的 `playbook.json` 做知识检索。配置 OpenAI Chat Completions 兼容端点后，平台自己跑一个有限步模型循环。

推荐在控制台「能力 → 模型」管理 provider：

- 可以添加多个 OpenAI 兼容端点，每个 provider 有名称、Base URL、模型列表、默认模型、超时/max tokens/温度、流式开关、重试次数/退避、输入输出单价和货币，以及启用/默认标记。
- API key 二选一：直接保存（AES-256-GCM 加密进 `data/model-providers.json`，权限 0600），或引用环境变量名（如 `AIOPS_MODEL_API_KEY`）。页面、任务事件和审计只显示「已配置」或环境变量名，不回显明文。
- 「测试」发一条极小的 chat completion 验证连通性和 key；「拉取模型」调 `GET {baseUrl}/models`，拉到的列表只填进编辑器，点保存才落盘。
- 默认走 SSE 流式输出，网页任务详情里能看到节流后的 `model.delta` 实时输出；provider 不支持流式（返回 400/404/405/415/422/501）时自动改用普通请求。
- 429、408、5xx、529、超时和网络错误会按指数退避重试（默认 2 次，首次 500ms）；已经开始输出增量后不再重试，避免重复内容。
- 每次模型调用的 prompt/completion/total token 累计到 `task.usage`，任务详情和 `model.step` 事件里可见；同时配置输入和输出单价时才估算成本，货币默认 USD。
- 提交平台任务时可以选择 provider 和模型；不选就用默认 provider 的默认模型。DSH/WorkBuddy 任务不经过这里，它们有自己的模型配置。
- 配置和测试/拉取接口只有 admin 能调用；列表对所有登录身份可见，方便任务表单选择，但不含 key。
- 配置变更写 `security_events`（`config.model_provider_saved` / `config.model_provider_deleted`），detail 不含 key。

只有**没有任何启用的 provider** 时，才回退到旧的环境变量或 `config/platform.json` 的 `model` 对象：

```sh
AIOPS_MODEL_BASE_URL=https://api.deepseek.com/v1 \
AIOPS_MODEL_NAME=deepseek-chat \
AIOPS_MODEL_API_KEY=... \
npm start
```

```json
"model": {
  "baseUrl": "https://api.deepseek.com/v1",
  "name": "deepseek-chat",
  "maxSteps": 8,
  "timeoutMs": 120000
}
```

`data/model-providers.json` 一旦有配置，就是权威数据；环境变量兜底不再生效。`AIOPS_MODEL_MAX_STEPS` 和 `AIOPS_MODEL_TOOL_OUTPUT_CHARS` 仍然全局生效，可以通过环境变量或 `model` 配置调整。

模型只能通过 ToolBroker 调工具：只读直接执行，变更生成审批，runner 等审批结果后自己续跑；拒绝或失败会回到模型上下文，模型可以继续换只读手段或如实结束。模型请求超时、接口报错、达到最大步骤都会让任务失败并写事件。单个工具结果回填前会截断，避免大列表把上下文打爆。这个执行器不是通用 Agent：没有长期记忆、没有多会话、没有自建工具。

注意：工具结果会发送到配置的模型端点，包括 `ssh.exec` 输出和 MCP 返回内容。不要把模型端点指向不可信服务；涉及密钥时先在工具侧脱敏。

`data/credentials.json`、`mcp-servers.json` 里的密码、私钥、passphrase、headers 用 AES-256-GCM 加密后落盘（`enc:v1:` 前缀），接口和页面仍只返回 `hasXxx` 布尔值。旧明文数据在启动加载时自动就地迁移成密文；密钥丢失或与数据不匹配会直接启动失败，不会清空或回退明文。密钥要跟 `data/` 一起备份：`openssl rand -base64 32` 生成后放进 `AIOPS_SECRET_KEY`，或保留 `data/secret.key`。

安全事件（登录成功/失败、登出、改密、用户和 API key 操作）配置变更（MCP、资产、凭证、知识文档、模型 provider）和任务重试（`task.retried`）写入 `security_events` 表，只记录用户名、用户 ID、IP、操作类型和标识类 detail，不记录密码、token 或私钥。`GET /api/security-events?limit=20&offset=0`（admin/auditor，`limit` 1-500）按最新在前分页，返回 `{ events, total, limit, offset }`；控制台「账号 → 安全事件」按每页 20 条展示。API key 的使用事件做了降噪：同一个 key 闲置超过 1 小时后的首次使用才记一条，持续调用不会每次刷新事件；`lastUsedAt` 仍按 60 秒节流更新。

### 3.1 用户和 API key

控制台左侧「账号」是二级菜单，和资产、能力一致：安全设置、API Key、用户管理（admin）、安全事件（admin/auditor），无权限的子项不显示；每个子页只加载自己的数据，安全事件按需刷新，不参与 1.2 秒轮询。

- 任何登录用户都能改自己的密码、创建/吊销/轮换自己的 API key（`POST /api/auth/keys`、`DELETE /api/auth/keys/{id}`、`POST /api/auth/keys/{id}/rotate`，仅网页会话可用）。
- 管理员能创建用户、停用/启用用户、重置密码、管理所有人的 key。停用或降级最后一个管理员会被拒绝。重置密码会弹出对话框，新密码和确认密码默认掩码显示，可勾选「显示密码」核对；两次输入必须一致且至少 12 个字符，校验失败在对话框内提示，不会关闭窗口。重置成功后该用户的网页会话全部失效，下次登录强制改密，同时清掉该用户的登录失败记录。用户表下方「登录失败与锁定」列出最近一个失败窗口内的用户名、来源 IP、失败次数和锁定截止时间；点「解锁」按用户名清掉所有来源 IP 的失败记录，只清计数，不修改密码或账号状态。
- 创建用户时密码可以留空：这种账号只能通过 API key 使用，不能网页登录，适合 DSH/WorkBuddy 这类客户端。`approver`、`auditor`、`admin` 必须有密码。勾选“创建时签发 API key”会在建号的同时发一把 key，token 只显示一次，会出现在签发页面顶部高亮的「新 API token」卡片里，带「复制」和「我已保存」按钮（切换页面或刷新后立即清空，返回原页面不会再次显示）；已有账号可以在用户表里点“签发 key”补发。
- API key 明文只在创建时返回一次，库里只存 SHA-256；key 有 scope：`tasks:read`、`tasks:write`、`approvals:read`、`approvals:write`、`tools:execute`、`knowledge:read`。管理员建号或补发时按角色给默认 scope：operator 拿全套执行/审批 scope，viewer 和 auditor 只拿读类。
- key 可以设置过期时间；过期的 key 认证直接失败，页面显示「已过期」。设置 `AIOPS_API_KEY_TTL_DAYS` 后，未填过期时间的新 key 自动按这个天数过期。
- 「轮换」会立即签发同名、同 scope 的新 key（有效期沿用旧 key 的时长），并吊销旧 key；新 token 只显示一次，适合定期换钥和泄露处置。已吊销的 key 不能再轮换。
- key 到期前默认 7 天（`AIOPS_API_KEY_REMIND_DAYS`）会通过已配置的通知渠道发一条 `api_key.expiring`，内容只有 key 名称、用户和到期时间，不含 token。过期/吊销的记录默认保留 30 天（`AIOPS_API_KEY_RETENTION_DAYS`）后清理；提醒按进程内去重，重启后可能重复提醒一次。
- 账号表不存 token 明文，只存 SHA-256；`security_events` 记录 `keyId`、key 名称和 `issuedBy`，能查到是谁给谁签发的。
- API key 不能访问用户管理和改密接口。

初始密码或被管理员重置的密码在改密前只能访问 `/api/auth/me`、改密和登出，其它接口返回 403 `password_change_required`；网页登录后会直接跳到「账号 → 安全设置」并只显示改密表单。API key 不依赖密码，不受这个限制。

「安全设置」会列出当前用户的全部活跃网页会话（创建时间、最近活动、到期时间、IP/UA），可以单独注销某个会话或「注销其他会话」；注销当前会话会同时清 Cookie。会话标识是随机的不透明 ID，响应里没有 token 或 hash。

审计导出：`GET /api/security-events/export`（admin/auditor）和 `GET /api/tasks/{id}/audit/export`（沿用任务可见性）支持 `format=csv`（默认）或 `json`，安全事件可按 `since` / `until` / `type` 过滤，单次最多 5000 条。CSV 带 UTF-8 BOM，可直接用 Excel 打开；导出内容与接口列表一致，不含密码、token、私钥或 webhook 明文。

硬规则：

- 第三方 MCP 中的变更工具（`risk: mutate`）不会直接执行，先产生待审批；只读 MCP server 需要在配置里显式 `readOnly: true`。
- 管理员可以在「能力 → 工具」里逐个覆盖 MCP 工具的默认风险，标成只读（不审批）或变更（走审批）。覆盖按工具签名生效，上游描述或参数一变就自动失效，回到默认分类。非 admin 不能改风险，只能改 MCP 连接配置。工具页按能力域（知识库 / 资产 / SSH）和上游 MCP server 分组，组头显示工具数和生效风险的只读/变更统计，工具超过 12 个的组默认收起，展开状态在本次页面会话内保持（整页刷新后回到默认）；顶部「展开全部 / 收起全部」一键切换。
- 任务所有者默认不能审批自己名下的变更。只有显式设置 `AIOPS_ALLOW_ADMIN_SELF_APPROVAL=1` 时，admin 才可以自批；approver/operator 始终不行。开启后网页会让 admin 二次确认，审批事件的 `data.selfApproved` 为 `true`，审计仍记录同一 actor，事后可识别。
- 审批只执行一次，重复使用会被拒绝。
- 审批被拒绝或任务被取消，都不会改集群；取消任务会同时把该任务的待审批置为拒绝并写入审计。任务还有挂起审批时，`POST /cancel` 必须显式传 `{"force":true}`，否则返回 409；网页会二次确认，DSH 侧的 `task.cancel` 默认被拒绝，避免 Agent 等审批时误取消。
- 挂起审批默认 24 小时过期，自动以 `system` 身份拒绝并写审计；外部 Agent 任务（`origin=dsh/api`）没有其他挂起审批时标失败。`AIOPS_APPROVAL_TTL_MS=0` 可关闭。

## 4. 控制台

打开 `http://127.0.0.1:8787`。

页内提示条分成功（绿色）、警告（橙色）和失败（红色）三档；保存配置、连接测试、模型连通性检查等结果都写在对应页面内，失败提示会自动滚到视野内，过长的页面也不用回头找。这些提示和一次性 token 一样只在当前页面有效，切换到其它页面就会清空，返回时不会看到上次的测试或保存结果；顶部全局错误条也会一并清掉，它同样是红色高亮并自动滚入视野，轮询刷新不会重复触发滚动。

### 总览

登录后默认进入「总览」，它按当前身份的可见范围汇总平台状态，不额外扩大权限。

- 四张指标卡：待处理审批、活跃任务（排队/执行中/待审批）、本地知识文档数、MCP 健康连接数。
- 「待处理审批」只列当前身份可见的最近 3 条，点条目直接聚焦审批页；「活跃任务」点进去看任务列表。
- 「最近任务」显示最近 5 条任务的来源、提交人和状态，点击直接打开任务详情。
- 「运行概况」有任务状态分布条：排队、执行中、待审批、完成、失败、已取消；点状态图例会带着这个状态跳到任务列表。下面汇总工具（只读/变更/MCP）、MCP 连接、资产和主机密钥未信任数。
- 任务和审批计数与列表使用同一套可见性规则：operator/viewer 只统计自己的，approver 额外包含有审批记录的任务，auditor/admin 看全部。viewer 看不到知识文档数和 MCP 统计，页面显示「当前身份不可见」。
- 总览数据来自 `GET /api/overview`，约 4 秒刷新一次；其他页面仍是 1.2 秒轮询。API key 不能调用这个接口，它只服务网页会话。

### 任务

- 提交时可写标题、问题和技能；技能留空时按关键词自动选择。配置了模型 provider 后，还可以选择本次任务使用的 provider 和模型，不选就用默认项。
- 任务列表可按状态、提交人筛选，每页 20 条。
- 详情页显示最终结论、每次工具调用的参数和返回、审计记录；等待审批时能直接看到变更参数并跳到审批页。过程超过 100 条时只显示最近 100 条，并提示总数。
- 最终结论按 Markdown 渲染（标题、列表、表格、代码块、链接），原始 HTML 不解析，链接只放行 http/https。
- 点左侧任务列表立即高亮并单独拉详情，不等整页轮询；旧详情请求的迟到响应会被丢弃，不会盖掉当前选择。
- 未结束任务可以取消；取消后挂起的审批一并作废。点「取消任务」会先确认，因为有挂起审批时取消等于放弃这次变更。
- 平台网页任务（`origin=web`）失败后，详情页右上角会出现「重试任务」；确认后复制原 prompt、技能和失败前 `task.started` 里记录的 provider/model 新建一条任务，原任务和审计保留，新任务事件 `task.retried` 带 `fromTaskId`、`actorId`、`fromOwnerId`（原 owner）和可选的 `fromRejectedApproval`，同时写一条 `task.retried` 安全事件（只记任务号和身份，不记 prompt）。只有 owner 和 admin 能重试，且仅限 `failed` 状态；admin 代重试时新任务归 admin。告警排查任务（`origin=alert`）和 DSH/外部 API 任务不提供重试，由发起方按原流程重新发起。重试会按任务保留策略把复制出的 prompt 多留一个周期（默认 30 天）。

### 审批

- 默认看「全部」，也可以切到待处理、已通过、已拒绝；每页 20 条。
- 审批人可以在通过或拒绝时写意见，意见进审计；挂起超过 24 小时的审批会自动拒绝，页面显示处理人是 system。
- 卡片上的「查看任务」跳回来源任务。
- 默认不能审批自己提交的变更；当前身份不是审批人时只读。部署时设置 `AIOPS_ALLOW_ADMIN_SELF_APPROVAL=1` 后，admin 在自己名下的审批上也会看到操作按钮，点「通过」会二次确认，事件里标 `selfApproved`；approver 仍然不能自批。

### 知识库

「知识」页是一个文档工作台：左侧列表、右侧详情，检索和文档管理共用同一块区域。

- 默认左侧列出全部本地文档，点一条在右侧看全文；搜索后列表切换为结果，显示来源和分数。
- 「清除搜索」回到全部文档列表。
- 右侧详情里对本地文档有「编辑」「删除」；「新建文档」在右侧打开编辑器，保存后自动打开该文档。
- `actors` frontmatter 只影响知识检索和 `knowledge.get_document` 工具；operator 及以上在管理页能看到并打开全部本地文档（列表里会显示限定的 actors）。外部知识库由对应服务按 `x-actor-id` 过滤。
- 可调返回条数 3/5/10/20。
- 文件落在 `data/knowledge/*.md`，首次启动从 `extensions/knowledge/fixtures` 复制示例。
- 外部知识库（RAGFlow/Dify/generic）的文档只读，不显示编辑入口，直接调管理 API 会返回 409。

### 资产

- 左侧「资产」是二级菜单：资产列表、资产管理、密码私钥管理。
- 资产列表是只读表格，显示主机/IP、SSH 用户、引用的凭证、负责人和等级。
- 资产管理负责名称、主机、IP、环境、负责人、等级、仓库、SSH 端口、SSH 用户，并选择一个 SSH 凭证；管理员还可以配置「SSH 只读日志路径」（`sshReadPaths`，每行一个绝对路径），决定 `ssh.logs` 能读哪些目录，operator 保存资产时不会覆盖已有路径。
- 资产列表和资产卡片的「测试连接」会真实登录一次（含认证、跳板机转发和主机密钥校验），不执行任何命令，返回 `user@host:port`、经过的跳板机、主机密钥指纹和耗时；接口是 `POST /api/assets/:name/ssh-test`，operator 及以上可用，结果写安全事件 `config.asset_ssh_tested`。主机密钥没信任、凭证缺失、认证失败、连接超时/被拒绝都会直接提示，常见 ssh2 错误会翻译成中文，这正是新增机器后确认「到底能不能连」的入口。连接结果只显示在资产页提示条，不占用顶部全局错误条。
- 密码私钥管理独立维护凭证：每一条只能是密码或私钥，二选一；资产只引用凭证 ID，不直接保存明文。
- 资产在 `data/assets.json`，凭证在 `data/credentials.json`，两个文件权限都是 0600；没有 CMDB 时用本地资产替代。
- 模型可以通过 `asset.list`、`asset.get` 读取，任务里需要归属时用得上。

### 能力

- 左侧「能力」是二级菜单：工具、技能、MCP、模型、通知、告警接入，默认收起。
- 工具：区分只读和变更，列出参数类型、必填和说明。管理员可以在每个 `mcp.*` 工具上单独覆盖风险：跟随默认、只读（不审批）或变更（走审批）；降级为只读会二次确认。页面会标出覆盖来源（人工 / 已失效 / 默认），上游工具变化导致签名不匹配时显示「已失效」，实际按默认风险执行。
- 技能：显示描述、关键词和完整排查说明。
- MCP：在线编辑 JSON 并保存。配置在 `data/mcp-servers.json`，保存前先探测上游，探测失败返回 502 且不落盘；headers 不回显。连接信息（地址、headers、超时、排除工具）operator 及以上可改；`readOnly` / `mutateTools` 属于风险配置，只有 admin 能改，避免普通账号把写 server 标成只读绕过审批。
- MCP 配置保存后会自动重建工具并立即生效。DSH 侧由 stdio 代理轮询工具列表并发送 `notifications/tools/list_changed`，新会话或重连后可见。
- MCP 列表有「健康」列：后台默认每 30 秒对各 server 做一次 `initialize` + `tools/list`。连续失败 3 次才摘除该 server 的工具，避免一次网络抖动下线；恢复后下一次巡检自动注册回来。也可以用「健康检测」按钮立即检查。巡检间隔用 `AIOPS_MCP_HEALTH_MS` 调整，单位毫秒，设为 `0` 关闭。
- 巡检发现上游工具集和上次复核基线不一致时，健康列显示「需复核」，悬停能看到新增、移除和签名变化的工具名。这表示风险分类可能已经不准确：先确认新工具是只读还是变更，更新 `readOnly` / `mutateTools`，再点「确认复核」把当前工具集设为新基线。确认只清标记，不会自动调整风险分类。
- 模型：管理员维护平台任务执行器的 OpenAI 兼容 provider，可以新增、编辑、删除、测试连接和拉取模型列表；其他身份只能读取列表。API key 加密落盘且不回显，直接填 key 和引用环境变量二选一。
- 通知：管理员配置钉钉、企业微信或通用 webhook，选择订阅审批待处理、审批超时、任务失败、MCP 不可用/恢复/工具集变化、SSH 主机密钥更换。webhook URL 加密落盘，页面只显示 host；同一实体在最小间隔内只发一条。
- 告警接入：管理员为夜莺 v6、Alertmanager 或通用 JSON 建接入源，拿到一次性 Token 和回调地址；告警进来后平台自动发起只读排查，结果按接入源勾选的渠道推送。详见 [6.12 告警接入](#612-告警接入)。
- 平台不再维护本地直连连接；所有外部系统都必须通过上游 MCP server 接入。

页面默认每 1.2 秒轮询一次，总览页约 4 秒一次。`GET /api/tasks/{id}/events?stream=1` 的 SSE 端点留给外部客户端，浏览器端没有接。任务和审批列表支持 `limit`（1–200）和 `offset`，响应带 `total`；事件和审计的 `limit` 取最近 N 条，响应带 `total`。控制台任务/审批每页 20 条，详情只展示最近 100 条过程和审计。

## 5. 接口

header 模式下，除 `/health`、`/login` 和 `/api/actors` 外都要求 `x-actor-id`。账号模式下改用 `Authorization: Bearer <API key>`；网页会话走 Cookie，写操作还要带 `x-csrf-token`。API key 按 scope 放行，`/api/users`、改密等管理接口不允许 key 访问。

通用限流：`/api/*` 和 `/mcp` 按客户端 IP 计数（默认 1200 次/分钟），登录按 IP 单独计数（默认 15 次/分钟），写请求再按账号计数（默认 60 次/分钟）。超限返回 429、`error.code=rate_limited` 和 `Retry-After` 头，`/metrics` 里 `aiops_rate_limited_total{scope=...}` 计数。`/health`、`/ready`、`/metrics`、`/openapi.json` 和静态页面不受限。HTTP 限流计数在进程内存，多副本各自计算；账号登录失败锁定（用户名 + IP，默认 5 次/15 分钟）在 MySQL，多副本共享。客户端 IP 默认取 TCP 对端；只有平台不能绕过反向代理直接访问时才设 `AIOPS_TRUST_PROXY=1`，此时取 `X-Forwarded-For` 最右侧地址，避免客户端伪造左侧条目。网页按 1.2 秒轮询，空闲任务详情页约 6 个请求/轮；遇到 429 时前端会按 `Retry-After` 静默暂停轮询，不会弹错误。

```sh
curl -s -b /tmp/aiops.cookie http://127.0.0.1:8787/api/auth/me

curl -s http://127.0.0.1:8787/api/tasks -H 'authorization: Bearer aiops_key...'

curl -s -b /tmp/aiops.cookie 'http://127.0.0.1:8787/api/security-events?limit=20&offset=0'

# 审计导出（CSV/JSON；安全事件可加 since/until/type，最多 5000 条）
curl -s -b /tmp/aiops.cookie -OJ 'http://127.0.0.1:8787/api/security-events/export?format=csv&type=auth.login_failed'
curl -s -b /tmp/aiops.cookie -OJ 'http://127.0.0.1:8787/api/tasks/task_xxx/audit/export?format=json'

# 网页会话：列出、注销指定会话、保留当前会话注销其它会话
curl -s -b /tmp/aiops.cookie http://127.0.0.1:8787/api/auth/sessions
curl -s -b /tmp/aiops.cookie -X DELETE -H "x-csrf-token: $CSRF" \
  http://127.0.0.1:8787/api/auth/sessions/sess_xxx
curl -s -b /tmp/aiops.cookie -X DELETE -H "x-csrf-token: $CSRF" \
  http://127.0.0.1:8787/api/auth/sessions
```

## 6. 接入真实数据

### 6.1 最小步骤

1. 备份 `config/platform.json` 和 `data/mcp-servers.json`。
2. 在「能力 → MCP」里编辑 `mcpServers` JSON，或改 `config/platform.mcp.json` 的 `mcpServers` 种子。
3. 按需改知识库 `knowledge.provider`。

`data/mcp-servers.json` 在 Web 保存后热加载，不需要重启；`config/*.json` 的改动需要重启。运行时以 `data/` 为准，`config/` 只在对应文件不存在时作为种子。

### 6.3 MCP server 配置

`data/mcp-servers.json` 是 `{ "servers": [...] }`；保存接口也接受顶层数组，落盘后统一写成对象。每项字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 唯一名字，工具前缀为 `mcp.<name>.<tool>` |
| `system` | `prometheus`、`kubernetes`、`loki`、`elasticsearch` 之一，用于页面分类 |
| `url` | Streamable HTTP MCP 地址，只支持 `http://` / `https://` |
| `readOnly` | 显式声明整台 server 只读；不写按变更处理（失败关闭） |
| `mutateTools` | 只读 server 里仍会写数据的工具名，例如 `helm` |
| `excludeTools` | 完全不暴露给平台的上游工具名，写 `alerts` 这种原始名字，不要带 `mcp.<name>.` 前缀 |
| `headers` | 上游认证头，值落盘前加密，接口不回显；值支持 `${ENV_NAME}` 占位符，例如 `Authorization: Bearer ${MCP_K8S_TOKEN}` |
| `timeoutMs` | 单次调用超时，可选；只限制「上游迟迟不返回」的等待，SSE 流在拿到匹配响应后立即断开，报错也会立即返回 |

风险规则：`readOnly: true` 且不在 `mutateTools` 里的工具是只读；其余全部按 `mutate` 处理，必须走审批。上游工具描述或参数变化时页面显示「需复核」，确认后只清标记。

管理员可以在页面上对单个 `mcp.*` 工具覆盖这个默认值，覆盖记录在 `data/tool-policies.json`（0600，与资产同级的运行数据，重启不丢）。每条记录带工具签名（名称 + 描述 + 参数的 SHA-256）：上游工具描述或参数一变，签名不匹配，覆盖自动失效并回退默认风险，页面标「已失效」。`GET /api/tool-policies` 登录即可读；`PUT/DELETE /api/tool-policies/:tool` 仅网页登录的 admin 可用，API key 都不能调；修改写审计。删除覆盖记录即恢复 server 默认。工具被摘除或改名后，页面会提示清理对应的残留记录。

### 6.4 Kubernetes

K8s 通过上游 MCP 接入，例如 `mcp.kubernetes-server`。平台不直连 API Server，也不需要 kubeconfig。

- 只读 server：建议启动参数带 `--disable-write --disable-delete`，配置里写 `readOnly: true`。
- 真实变更：需要单独接一台具备写权限的 MCP server，只给它最小 RBAC（例如仅目标 namespace 的 patch/delete）；配置里不要写 `readOnly: true`，对应工具会自动进入审批。
- 没有写权限的 MCP server 上，不要在技能里承诺能重启或删除；平台没有内置的 `k8s.restart_workload` / `k8s.delete_pod` 兜底工具了。
- 多集群：每个集群一个 MCP server，名字区分（如 `k8s-prod`、`k8s-cluster-a`），技能按 server 名引用。

### 6.5 日志：Loki 和 Elasticsearch

日志同样通过 MCP server 接入。ES 场景把上游的 search 工具暴露成 `mcp.<server>.<tool>`，索引和鉴权都配在上游 server 侧，平台不再保存 ES 地址、用户名、密码或 API Key。

ES 字段提醒（`dw_syslog_*` 只有这些）：`@timestamp`、`filebeat_time`、`host`、`host_ip`、`ident`（程序名）、`message`、`pri`（text）、`pid`（text）、`time`。查询里不要写 `program`、`severity`、`log.level` 这些不存在的字段；写错不会报错，只会返回空结果。`host` 是主机名、`host_ip` 才是 IP；`host` / `ident` 是 text 字段，精确匹配、`prefix` 和聚合用 `host.keyword` / `ident.keyword`，对 text 字段聚合会 400。ES 8.3.2 不支持 `esql`，用 `search` / query DSL。

### 6.6 本地资产（替代 CMDB）

CMDB 连接已经从平台移除，现有 CMDB 接不进来时直接用本地资产页。

资产存在 `data/assets.json`，字段：

```json
{
  "name": "checkout-api",
  "host": "checkout-api-7d9c",
  "ip": "10.0.0.12",
  "env": "prod",
  "owner": "shop-team",
  "tier": "critical",
  "repo": "git.example/shop/checkout",
  "sshPort": 22,
  "sshUser": "ops",
  "sshCredentialId": "cred_xxx",
  "sshJumpAsset": "jump-bastion",
  "note": "可选备注"
}
```

凭证独立存在 `data/credentials.json`：

```json
{
  "credentials": [
    { "id": "cred_xxx", "name": "prod-root", "type": "password", "password": "登录密码" },
    { "id": "cred_yyy", "name": "prod-key", "type": "key", "privateKey": "OpenSSH/PEM 私钥全文", "passphrase": "可选" }
  ]
}
```

- 左侧「资产」是二级菜单：资产列表、资产管理、密码私钥管理。
- 资产管理里只有一个「SSH 凭证」下拉，选择一个凭证；不会同时出现密码和私钥输入框，所以天然二选一。
- 密码私钥管理里每条凭证的 `type` 只能是 `password` 或 `key`，二选一；列表和接口只返回 `hasSecret`，不回显密码或私钥。
- 两个数据文件权限都是 0600；资产只保存凭证 ID，内联的 `sshPassword` / `sshKey` / `sshPassphrase` 和凭证字段一样用 AES-256-GCM 加密落盘。
- 编辑资产时选改凭证；编辑凭证时密码/私钥留空表示保留原值。凭证被资产引用时不能删除，返回 409。
- 旧数据里的内联 `sshPassword` / `sshKey` 仍然兼容，但页面新增和编辑只走凭证引用。
- 模型侧工具：
  - `asset.list` / `asset.get`：查资产，不返回凭证内容。
  - `ssh.test`：按资产登记测试 SSH 连接，只读，不执行命令；要求资产已经信任主机密钥。
  - `ssh.read`：执行白名单里的系统诊断命令，**只读，直接执行并审计**，不产生审批。命令按空格切分后逐 token 校验字符集，再与固定模板精确匹配，不经过远端 shell，管道、重定向、引号、通配符、命令替换一律拒绝。白名单覆盖身份/内核（`hostnamectl`、`uname -a`、`whoami`、`id`、`date`、`uptime`、`lscpu`）、负载内存（`free -m/-h/-g`、`vmstat 1 3`、`vmstat -s`）、磁盘（`df -h/-i/-hT/-Th/-P`、`lsblk`/`lsblk -f`）、进程（`ps aux`、`ps -ef`、`top -bn1`）、网络（`ss`、`ip -br addr`、`ip route`、`ip neigh`）、systemd（`systemctl --failed --no-pager`、`systemctl status <unit> --no-pager`、`systemctl is-active|is-enabled <unit>`、`journalctl -p err|warning -n N --no-pager`、`journalctl -u <unit> -n N --no-pager`、`journalctl -k -n N --no-pager`）、内核日志（`dmesg -T --level=err,warn`）和固定的 `/etc/os-release`、`/proc/loadavg` 等只读文件；`journalctl -n` 上限 500。输出最多 64KB，超时默认 15 秒、最长 30 秒。参数是 `{ "asset": "host01", "command": "df -h" }`。
  - `ssh.logs`：读取资产声明的日志文件，**只读，直接执行并审计**。可读路径来自资产的 `sshReadPaths`（绝对路径，最多 20 条，仅管理员可改），只能按前缀匹配；平台先跑 `readlink -f` 解析软链、再 `stat -L -c %F` 确认是普通文件，软链指向允许范围之外直接拒绝。参数 `{ "asset": "host01", "path": "/var/log/nginx/error.log", "lines": 200, "grep": "error" }`：`lines` 是 1..500 的整数（默认 200），`grep` 是固定字符串匹配（不接受空白和 shell 特殊字符）。不传 `grep` 时等价 `tail -n N -- <file>`，传了等价 `grep -F -m N -- <pattern> <file>`。资产没配 `sshReadPaths` 时 `ssh.logs` 直接拒绝，读任意文件只能走 `ssh.exec`。页面资产表单里的「SSH 只读日志路径」只有管理员可见。
  - `ssh.exec`：在资产上执行命令，**变更操作，必须走审批**；审批页会显示资产名和完整命令，批准后才能执行。输出最多 200KB，超时默认 15 秒，可传 `timeoutMs`。
- 跳板机：资产的 `sshJumpAsset` 指向另一条资产，平台会先连跳板机，再用 SSH direct-tcpip 转发连目标；跳板机自己也必须是完整资产（用户名、凭证、已信任主机密钥），最多 4 层，链路不能成环。`ssh.test` / `ssh.read` / `ssh.logs` / `ssh.exec` 结果里的 `jumps` 列出经过的跳板机。仍被引用的跳板机资产不能删除（409）。
- known_hosts 导入：资产管理页「导入 known_hosts」（仅 admin）默认只预检，确认后再应用。平台按资产的主机名/IP + 端口匹配，只写入尚未信任且唯一匹配的指纹；已信任指纹永不覆盖，同主机多个指纹记为歧义，哈希主机名、通配符、否定模式和 `@cert-authority`/`@revoked` 条目直接跳过并列出行号。接口是 `POST /api/assets/known-hosts/import`，body `{ "content": "...", "apply": false }`，内容上限 256KB。
- SSH host key 校验：资产必须信任主机密钥后才允许 `ssh.test` / `ssh.read` / `ssh.logs` / `ssh.exec`。在资产页点「校验主机密钥」会只做握手、不发送凭据，拿到服务端指纹后由管理员确认信任（`POST /api/assets/:name/ssh-host-key/trust`，仅 admin）；`operator` 可以探测，但不能信任。
  - 指纹格式是 OpenSSH 的 `SHA256:<base64 无填充>`，存在资产的 `sshHostKeyFingerprint`，不是敏感信息。
  - 已信任后再探测发现不一致会拒绝连接，提示中间人或主机重装；确认替换时必须带旧指纹，防止旧页面静默覆盖。
  - 修改资产的主机、IP 或 SSH 端口会自动清除已信任指纹，必须重新校验。
  - 指纹信任和探测都会写安全/配置事件；指纹不匹配的 SSH 执行会被拒绝，不会执行命令。
- 启动时会写入两条演示资产（checkout-api / payments-api），可以直接删掉换成真实机器。
- 以后真要接 CMDB，再加连接器或 MCP，不应该恢复成平台内置的固定格式。

### 6.8 playbook 和平台模型执行

当前四个技能按任务类型划分：

- `k8s-troubleshooting`：Kubernetes 任务。排查工作负载、事件、调度和节点异常，要求把 K8s 资源、日志（`mcp.es.*`）和监控（`mcp.vm.*`）三方交叉验证后再下结论。
- `monitoring-analysis`：监控任务。用 VictoriaMetrics/PromQL 分析 CPU、内存、磁盘、网络、容量、throttling 和告警，定位异常对象、时间窗和影响范围。
- `log-analysis`：日志任务。检索 Elasticsearch 系统日志，按主机、`ident` 和时间窗定位错误、突增和首次异常，规避索引和字段陷阱。
- `ssh-troubleshooting`：SSH 任务。对已登记资产做主机侧只读取证（负载、内存、磁盘、进程、内核日志、网络），优先用 `ssh.read` / `ssh.logs` 直接取证，只有不在白名单或需要变更时才用 `ssh.exec` 走审批；全部校验主机密钥。

没有配置模型端点时，网页任务会执行对应技能目录下的 `playbook.json`。四个 playbook 只做知识检索：

```json
{ "tool": "knowledge.search", "args": { "query": "{{prompt}}", "top_k": 3 } }
```

`{{prompt}}` 会被替换成问题文本。这是降级路径，不会调用集群或日志工具。

在「能力 → 模型」配置 provider（或没有 provider 时用 `AIOPS_MODEL_BASE_URL` + `AIOPS_MODEL_NAME` 兜底）后，同一个任务入口改由平台模型循环执行：模型读取 `SKILL.md` 和问题，按需调用 MCP/知识/资产/SSH 工具，最多 8 轮；变更仍要审批，通过后本地 runner 继续。想强制回到 playbook，设 `AIOPS_MODEL_DISABLE=1` 后重启。真实复杂排查仍然建议通过 DSH 或 WorkBuddy 发起。

模型看到的工具描述里，`risk: mutate` 的工具会额外标注「变更工具：调用会进入人工审批」，系统提示也要求只读查询优先用 `k8s_get`/`k8s_describe`/`k8s_logs` 这类专用工具，不要为了筛选或排版改用 `kubectl`、`helm`。单个工具结果默认只回填 12000 字符；返回大对象（例如带 `managedFields` 的 Namespace/Node 列表）时结果会被截断，可以调大 `AIOPS_MODEL_TOOL_OUTPUT_CHARS`，或让模型用更窄的 namespace/name/label selector 查询。

### 6.9 凭据和安全

- `config/platform.json` 和 `.env` 里的数据库密码、`internalToken` 是明文。放到仓库外，并设成 `chmod 600`。K8s 用 Secret 注入 `AIOPS_INTERNAL_TOKEN` 覆盖配置里的值。
- 不要把带凭据的配置提交到 git。
- MCP headers 保存在 `data/mcp-servers.json`，敏感值用 AES-256-GCM 加密（`enc:v1:`），接口不回显。
- `internalToken` 保护 `/api/tool-calls`，只给 MCP 代理用，换环境必须换掉；账号模式优先用 API key。
- MCP 里的变更工具会真实执行写操作。先给上游 MCP 最小权限账号，在非生产验证后再切生产。
- 账号模式下未登录请求会被拒绝；header 模式（不设 `AIOPS_AUTH`）的 `x-actor-id` 可伪造，只用于本机调试，不要暴露到公网或办公网。

### 6.10 接已有 MCP Server

文章的顺序是“先看有没有现成 MCP，有就接，没有才写”。平台现在支持 Streamable HTTP 的上游 MCP，启动时调 `initialize` 和 `tools/list`，把工具注册成 `mcp.<server>.<tool>`。

本机开发示例见 `config/platform.mcp.json`。容器部署时典型的两个条目（ES 日志只读 + 有写权限的 K8s），token 用环境变量占位，不要把明文提交到仓库：

```json
{
  "servers": [
    {
      "name": "es",
      "system": "elasticsearch",
      "url": "http://mcp-es-auth:8080/mcp",
      "readOnly": true,
      "mutateTools": [],
      "headers": { "Authorization": "Bearer ${MCP_ES_TOKEN}" }
    },
    {
      "name": "k8s-prod",
      "system": "kubernetes",
      "url": "http://mcp-k8s-prod-auth:8766/mcp",
      "readOnly": true,
      "mutateTools": [
        "k8s_create", "k8s_expose", "k8s_run", "k8s_set_resources", "k8s_set_image", "k8s_set_env",
        "k8s_rollout_undo", "k8s_rollout_restart", "k8s_rollout_pause", "k8s_rollout_resume",
        "k8s_scale", "k8s_autoscale", "k8s_cordon", "k8s_uncordon", "k8s_drain", "k8s_taint", "k8s_untaint",
        "k8s_exec_command", "k8s_port_forward", "k8s_cp", "k8s_apply", "k8s_patch", "k8s_label",
        "k8s_annotate", "k8s_delete", "kubectl", "helm"
      ],
      "headers": { "Authorization": "Bearer ${MCP_K8S_TOKEN}" }
    }
  ]
}
```

`${MCP_ES_TOKEN}` / `${MCP_K8S_TOKEN}` 要在平台进程的环境变量里存在；页面里也可以直接填明文 token，平台加密后落盘，接口和页面不回显。

`config/platform.mcp.json` 里的 `mcpServers` 只在 `data/mcp-servers.json` 不存在时作为种子。之后在「能力 → MCP」里直接编辑 JSON 并保存，文件权限 0600，保存前校验：

- 保存接口接受顶层数组或 `{ "servers": [...] }`；每项字段只允许 `name`、`system`、`url`、`readOnly`、`mutateTools`、`excludeTools`、`headers`、`timeoutMs`。
- `name` 必填且唯一，`system` 必须是 Prometheus/Kubernetes/Loki/Elasticsearch，`url` 必须是 http(s)。
- `readOnly` 是布尔值；`mutateTools` / `excludeTools` 是字符串数组；`headers` 是字符串键值对；`timeoutMs` 是 1000-60000 的整数。
- 保存前会按新配置初始化每个 MCP server；任一 server 初始化失败，接口返回 502，`data/mcp-servers.json` 保持原样，旧工具继续可用。
- 平台启动时如果某个 MCP server 不可达，只跳过这一家、记录错误（页面「MCP」页顶部会显示），其余工具照常注册，平台不会因此起不来。
- 启动后会立即巡检一次，之后默认每 30 秒一次。单个 server 连续失败 3 次，平台摘除 `mcp.<server>.*` 工具并记入错误；恢复后自动重新注册。其它 server 不受影响，也不需要重启平台。
- `headers` 里可能有认证信息，只在本地可信环境使用。

启动：

```sh
npm run start:mcp
# 等价于 AIOPS_CONFIG=config/platform.mcp.json npm start
```

规则：

- `readOnly: true` 表示这个 server 的工具默认只读；不写或写 `false` 时全部按变更处理，失败关闭。
- `mutateTools` 用来覆盖只读 server 里的可写工具。只读模板（`--disable-write`）通常只需要标 `helm`；没有禁用写操作的上游 MCP，必须把 `tools/list` 返回的写工具全部列进去，漏掉的会被当成只读自动执行。有写权限的 K8s MCP 当前是 27 个写工具（`k8s_create` 到 `k8s_delete`，加 `kubectl`、`helm`），完整列表见 `deploy/mcp-k8s-write/README.md`。
- `excludeTools` 可以完全不暴露某个上游工具。如果不想要 `helm`，把它加进 `excludeTools`。
- 工具名是 `mcp.<server>.<tool>`，例如 `mcp.es.search`、`mcp.vm.query_range`、`mcp.k8s.k8s_logs`。
- 调用经过平台的 ToolBroker：只读写审计，变更生成审批；DSH 通过 `npm run mcp` 看到同一批工具，任务事件里能看到 `mcp.*` 调用。
- 上游 MCP 的凭据由它自己管理。比如 Elasticsearch MCP 的 ES 地址和密码在容器环境变量里，平台只配 MCP 的 URL，不接触 ES 密码。
- 保存配置前的探测是失败关闭；启动和热加载时相反，单个 server 连不上只跳过并记录错误。
- 如果平台跑在容器里，`127.0.0.1` 不通，要换成 `host.docker.internal` 或同一 Docker 网络里的服务名。
- ES MCP 暴露的 `esql` 在 Elasticsearch 8.3.2 上不可用；用 `mcp.es.search` 传完整 query DSL。

注意：Kubernetes MCP 的 `k8s_get` 能读任意对象，包括 Secret；它的权限边界在容器里的 kubeconfig/RBAC，不在平台的只读标注。需要限制时收紧 MCP 侧的 ServiceAccount，不要靠风险标签。

### 6.11 通知和可观测性

通知（「能力 → 通知」）：

- 支持钉钉机器人（`msgtype=markdown`）、企业微信机器人（`msgtype=markdown`）和通用 JSON webhook。
- 钉钉「加签」：在 webhook 表单里填机器人安全设置里的 `SEC...` 密钥，发送时按官方算法在 URL 追加 `timestamp` 和 `sign`（`base64(HmacSHA256(timestamp + "\n" + secret, secret))`）。密钥用 `secret-box` 加密落盘，接口和页面只返回 `hasSecret`；编辑时留空保持原值，勾选「清除已保存的加签密钥」才删除。加签只对钉钉格式生效。
- 订阅事件：`approval.pending`（新审批）、`approval.expired`（审批超时自动拒绝）、`task.failed`、`mcp.unhealthy`（连续失败达到阈值、工具摘除）、`mcp.recovered`、`mcp.tools_changed`（上游工具集变化待复核）、`asset.host_key_changed`（管理员重新信任了不同指纹）。
- 配置存 `data/notifications.json`（0600），webhook URL 用 `enc:v1:` 加密；接口、页面、审计和日志只出现 host，不回显完整 URL。编辑时 URL 留空表示保持原值。
- 非本机地址必须用 https；本机 `127.0.0.1` / `localhost` 允许 http，方便本地收包联调。
- 同类事件按「webhook + 事件类型 + 实体 id」节流，默认 60 秒（`minIntervalMs`，0 关闭）。审批超时会同时产生 `approval.expired` 和（如果任务因此失败）`task.failed`。
- 投递 5 秒超时，失败只记 `aiops_notifications_total{result="failed"}` 和结构化日志，不会让审批或任务失败；没有自动重试。告警定向推送的每个渠道结果会写到任务事件 `alert.notify`。
- `approval.pending` / `approval.expired` 消息带平台深链 `/#/approvals/<审批id>`（通用 JSON 的 `link` 字段、钉钉/企微 markdown 的链接），点开直接定位到审批卡片。没登录会先跳到登录页，登录后回到原审批，不会掉到首页。
- 深链只是打开页面，不携带审批权限：仍然要用 approver 账号登录，平台照常检查「不能审批自己提交的变更」。基地址用 `AIOPS_PUBLIC_URL` 配置，默认 `http://127.0.0.1:<port>`。

指标 `GET /metrics`（Prometheus 文本格式）：

- `aiops_up`、`aiops_uptime_seconds`、`process_resident_memory_bytes`、`process_heap_bytes`。
- `aiops_tasks{status}`、`aiops_approvals{status}`、`aiops_pending_approvals`、`aiops_tools{risk}`。
- `aiops_mcp_server_up{server}`、`aiops_mcp_server_failures{server}`、`aiops_mcp_review_required{server}`。
- `aiops_security_events_total`、`aiops_notifications_total{result,type}`、`aiops_http_errors_total{code}`、`aiops_alert_hooks_total{result}`（`created` / `resolved` / `below_threshold` / `duplicate` / `capacity`）。
- 计数在进程内累计，重启清零；MCP 健康状态变化同时写 `security_events`（`config.mcp_unhealthy` / `config.mcp_recovered` / `config.mcp_tools_changed`）并触发通知。
- 不设置 `AIOPS_METRICS_TOKEN` 时匿名可读，只适合本机；对内网共享环境或 Ingress 暴露时必须设置。平台监听非回环地址且没有 token 时，启动日志会告警；K8s 的 `preflight.sh` 会直接判失败。

Prometheus 抓取配置带同一个 token：

```yaml
scrape_configs:
  - job_name: aiops
    metrics_path: /metrics
    authorization:
      credentials: <AIOPS_METRICS_TOKEN>
    static_configs:
      - targets: ['aiops.aiops.svc:8787']
```

日志：平台核心路径输出 JSON 行（`ts`、`level`、`msg` 和字段），info/warn 到 stdout，error 到 stderr；`AIOPS_LOG_REQUESTS=1` 时增加 `http.request` 访问日志（方法、路径、状态码、耗时）。日志不写密码、token、私钥和 webhook URL。

### 6.12 告警接入

外部监控把告警推到平台，平台自动发起一次**只读排查**，不执行任何变更；排查结果可以回推到指定通知渠道，也可以在平台任务页查看。

配置（「能力 → 告警接入」，仅 admin 可写）：

1. 新增接入源，选择格式：夜莺 v6、Alertmanager 或通用 JSON。名称只用于展示和去重，可中文，最长 64 位。
2. 选择归属账号（必须是 operator/approver/admin），告警任务以该账号身份创建。
3. 设置「排查最高级别」，默认 P1-P2（`maxSeverity=2`，只排查 severity ≤ 2 的告警）；冷却窗口默认 10 分钟。
4. 选择结果推送渠道；不选则只落平台任务页。可选设置默认技能和模型 provider/model，不设则按告警内容自动选择、用默认模型。
5. 保存后页面只显示**一次** Token 和接入地址，切换页面或刷新后清空；Token 只存 SHA-256，丢了只能轮换。

各监控的配置方式：

- **夜莺 v6 单规则回调**：在告警规则/通知配置里把回调地址填为 `http(s)://<平台>/api/hooks/alerts/<sourceId>`，请求头加 `Authorization: Bearer <token>`，请求体保持夜莺原始事件 JSON（`rule_name`、`severity`、`status`、`tags`、`annotations`、`hash`、`is_recovered` 等）。内网 HTTP 可用，但 Token 会在局域网内明文传输。
- **夜莺 v6 全局 Webhook**：通知媒介选 Webhook，URL 和 Header 同上；模板请求体可以是单个事件对象、事件数组，或 `{"events":[...]}` / `{"event":{...}}`。顶层数组只在告警接入接口放行，其他 API 仍要求 JSON 对象。字段名兼容 snake_case 和 camelCase；`tags`/`annotations` 支持对象、`k=v,k2=v2` 字符串和 JSON 字符串。严重级别优先读顶层 `severity`（也认 `level`/`priority`），顶层没有时回退 `tags.severity` / `tags.level` / `tags.priority`。
- **Alertmanager**：receiver 配 `webhook_configs`，`url` 同上，`http_config.authorization.credentials` 填 Token；标准 v4 payload（`alerts[]` + `labels`/`annotations`/`fingerprint`）直接可用。`labels.severity` 的 `critical`/`warning`/`info` 分别映射到 1/2/3。

行为约定：

- 只有 `firing` 且 `severity <= maxSeverity` 的告警会建任务；恢复通知返回 `{"accepted":false,"reason":"resolved"}`，低于阈值返回 `below_threshold`。
- 同一接入源、同一组 fingerprint 在冷却窗口内只排查一次，返回 `duplicate`；平台重启后冷却状态清空。
- 同时运行的告警任务默认最多 3 个（`AIOPS_ALERT_MAX_CONCURRENCY`），超限返回 `capacity`，不排队。
- 每个接入源每分钟最多 60 次回调，超限 429。
- 告警任务把所有 `risk=mutate` 工具从模型定义中剔除，执行层再拦一次，**不会产生变更审批**；任务失败时也会推送失败结果。
- 告警任务的归属账号和 operator 及以上角色可以看到；viewer 看不到。
- 结果推送使用通知事件 `alert.investigated`，只发给接入源勾选的 webhook，不受 webhook 的事件订阅限制，但仍受「能力 → 通知」的全局开关和最小间隔约束；消息带 `/#/tasks/<taskId>` 深链。
- 每次推送会在任务过程写一条 `alert.notify` 事件，记录每个渠道的成功/失败；没有投递到任何渠道时也会写空结果，便于排查全局开关、渠道停用或 webhook 被删。
- 接入源保存时校验 `notifyWebhookIds` 是否真实存在；仍被告警源引用的通知 webhook 不能直接删除，避免静默不推送。
- 「测试」按钮用模拟告警走完整链路，跳过冷却、允许停用源，仍受并发上限约束。

数据和安全：

- 接入源存 `data/alert-sources.json`（0600，`AIOPS_ALERT_SOURCES_FILE` 可改路径），文件损坏时启动失败，不会静默清空。
- 回调路由在会话认证之前，只认接入源 Token；`/api/alert-sources` 管理接口仍走正常登录/CSRF，审计记 `alert_source_saved` / `alert_source_removed` / `alert_source_token_rotated` / `alert_source_tested`，不记录 Token。
- 告警任务 `origin=alert`，任务表新增 `alert_source_id`，MySQL 自动迁移。
- 排查必须能解析到模型 provider；没有可用模型时任务直接失败并提示「告警排查需要先配置可用的模型 provider」，不会退回固定 playbook。
- 告警内容、日志、`describe` 和指标输出都会发送给所选模型 provider。上线前要确认数据合规、provider 的外发策略和网络边界；不要把不能出内网的日志接到外部模型。
- 上线前用只读 MCP 的 `tools/list` 对照平台 `/api/tools` 和「能力 → MCP」：`readOnly: true` 只是默认风险分类，不在 `mutateTools` / `excludeTools` 里的写工具会被当成只读暴露给告警任务。检查 `data/tool-policies.json`，不要保留把写工具覆盖成 `read` 的记录；给告警用的 MCP 账号只授予最小只读权限，不要让它能读 Secret、ConfigMap 或执行命令。

## 7. Web 化接入的现状和边界

已实现：

- 「能力 → MCP」可以编辑 JSON、保存、健康检测和复核工具集；资产、SSH 凭证、知识文档在页面管理。
- MCP 保存前在线探测；不可达时不落盘，返回 502，旧配置保留。
- 平台启动时容忍单个 MCP 不可达，只缺那一家的工具，并在页面显示错误。
- MCP 配置保存后热加载，工具集立即替换，`/api/tools` 和 DSH 工具列表跟着变。
- 后台 MCP 健康巡检：启动后立即探测一次，之后按 `AIOPS_MCP_HEALTH_MS`（默认 30 秒）轮询；连续失败 3 次摘工具，恢复后自动注册；页面有健康列和手动检测按钮。
- 工具集变化检测：巡检发现上游新增/移除工具或描述、参数变化时标记「需复核」并列出变化项，人工确认后清标记；MCP 配置重存引起的整体重建不会冲掉待复核状态。
- 热加载替换工具集会关闭上一轮上游 MCP session（DELETE，尽力而为）。
- 平台启动时回收中断的网页任务，标成失败并拒绝挂起审批；`origin=dsh/api` 的外部任务不动。
- 对外 `/api/v1` 支持创建任务、工具调用、事件、审计、结束/取消和审批查询，`GET /openapi.json` 提供规范。
- 账号模式已经启用登录鉴权、角色和 API key；header 模式只用于本机调试。
- 安全事件和配置变更写 `security_events`，admin/auditor 在「账号 → 安全事件」分页查看；任务/审批/事件/审计支持分页，挂起审批会过期，终态数据和事件有保留期清理。
- `data/` 里的密码、私钥和 MCP headers 用 AES-256-GCM 加密落盘，旧明文启动时自动迁移。
- API key 支持过期时间、默认 TTL 和轮换。
- 「能力 → 通知」支持钉钉/企业微信/通用 webhook，订阅审批、任务失败、MCP 健康和主机密钥变化事件，URL 加密落盘并做节流；审批通知带 `/#/approvals/<id>` 深链，登录后回到审批卡片。
- `GET /metrics` 输出 Prometheus 文本指标；核心路径改为结构化 JSON 日志，可选请求访问日志。

仍然没做：
- 钉钉/企业微信里点「同意」直接通过审批没有做。群机器人只能出站推送，收不到点击；要做需要企业内部应用或自建应用的消息回调、公网 HTTPS 回调地址、IM 用户和平台 approver 账号绑定，并校验点击者身份。当前只提供深链，审批动作留在 Web。
- 配置变更有事件记录，但没有按“变更前后差异”做 diff。
- 加密密钥默认也在本机 `data/secret.key`：能防数据文件被单独拷走，防不了主机被攻陷。生产建议用 `AIOPS_SECRET_KEY` 从密钥管理系统注入，并跟数据一起备份。
- API key 到期前没有通知，过期/吊销的 key 行也不会自动清理。
- HTTP 登录限流计数在进程内存，多实例不共享；账号登录失败锁定（用户名 + IP）在 MySQL，多实例共享。
- `/metrics` 的计数和节流状态也在进程内，重启清零、多实例各自统计；没有接入 OpenTelemetry / tracing。

结论：账号模式下已经是团队可用的配置管理页；MCP headers 和凭证仍建议只在本机或受控网段使用。

## 8. 接 DSH / MCP

DSH 是外部的 DeepSeek Harness，负责模型推理、会话、Skill 加载和 MCP client。它不在本仓库里，`harness/` 保持空白，需要单独部署；只用网页控制台时不需要它，平台会按 playbook 自己跑。

平台工具通过 stdio MCP 代理暴露给 DSH：

```sh
# 账号模式：用控制台「账号 → API Key」给 DSH 创建一个 API key
AIOPS_API=http://127.0.0.1:8787 \
AIOPS_API_TOKEN=aiops_key... \
npm run mcp

# 本机 header 模式才使用内部 token
AIOPS_API=http://127.0.0.1:8787 \
AIOPS_INTERNAL_TOKEN=dev-internal-token \
AIOPS_ACTOR=alice \
npm run mcp
```

代理优先读 `AIOPS_API_TOKEN`（Bearer），设置了就不再发送 `x-actor-id` 和 `x-internal-token`；任务归属和权限由 key 对应的用户决定。API key 至少需要 `tasks:read`、`tasks:write`、`tools:execute`，审批续跑还需要 `approvals:write`。

### 远程 DSH：直接连平台 `/mcp`

DSH 跟平台不在同一台机器（或不想由 DSH 拉起子进程）时，跳过 stdio 代理，直接配置平台的 MCP Streamable HTTP 端点：

```text
POST   http://<平台地址>:8787/mcp      # JSON-RPC，initialize 后带 Mcp-Session-Id
DELETE http://<平台地址>:8787/mcp      # 主动结束会话
Authorization: Bearer <API key>
```

- 认证和 stdio 代理一致：账号模式用 API key（scope 要包含 `tools:execute`，任务相关再给 `tasks:read` / `tasks:write`，审批续跑给 `approvals:write`）；header 模式用 `x-internal-token` + `x-actor-id`。
- 工具列表和 stdio 代理完全相同（`task.*`、`approval.*`、知识、资产、SSH、上游 `mcp.*`），审批规则也一样，变更仍然进审批队列。
- 每个 `initialize` 分配一个会话，会话内任务是同一个上下文（一个会话同时只承载一个任务，和 stdio 代理语义一致）；会话 30 分钟没请求自动回收，最多同时保留 100 个。
- 会话只在进程内，平台重启后客户端要重新 `initialize`；多实例部署时同一个会话必须落在同一实例（需要粘性会话）。
- 身份隔离：会话绑定发起 `initialize` 的用户，换 key 用同一 session id 请求返回 403；未知或过期会话返回 404，客户端应重新 `initialize`。

公网或跨不可信网段建议走 HTTPS。反向代理/Ingress 终结 TLS 时平台继续跑 HTTP，`AIOPS_PUBLIC_URL` 写成外部可访问的 `https://` 地址，`AIOPS_COOKIE_SECURE=1`。内网可信环境可以直接用 `http://<IP或域名>:<端口>`，但必须把 `AIOPS_COOKIE_SECURE` 设为 `0`，否则浏览器不会回传会话 Cookie；登录密码、API key 和告警 Token 会明文传输。

平台自己终结 TLS 时设置 `AIOPS_TLS_CERT_FILE` 和 `AIOPS_TLS_KEY_FILE`（最低 TLS 1.2），Cookie 自动加 Secure；两个变量只设一个会直接拒绝启动，证书读取失败同样退出。这种模式下 Docker HEALTHCHECK 和 K8s probe 必须改成 HTTPS，否则平台会被判不健康。

平台只监听 HTTP/HTTPS：`/mcp` 的 GET 返回 405（没有 SSE 推送），通知类请求（没有 id 的 JSON-RPC）返回 202。

在 DSH 里为这个代理单独配置一条 MCP server。工具调用仍然经过平台：只读直接执行，变更进入审批；连接地址和凭据只放在平台配置里。

注意技能边界：`extensions/aiops-skills/*/SKILL.md` 只由平台自己的任务执行器读取。DSH 通过 MCP 拿不到技能正文，`task.create` 里带的 `skill` 只用于任务标记和 `skill.selected` 事件，推理和工具选择由 DSH 完成。

代理在原有工具之外还暴露任务和审批工具：

| 工具 | 作用 |
| --- | --- |
| `task.create` | 建平台任务，后续工具调用挂在这个任务下；一个 MCP 进程同时只承载一个任务 |
| `task.finish` | 写最终结论或失败原因；有待审批变更时拒绝结束 |
| `task.get` | 查当前或指定任务的状态、最近 100 条事件和审计、关联审批 |
| `task.cancel` | 取消任务，挂起的审批一并作废；有挂起审批时默认拒绝，需显式传 `force:true`。审批等待期间不要取消 |
| `approval.list` | 查看审批队列 |
| `approval.get` | 查审批决定和自动执行结果（`execution.status/result/error/auditId`）；审批通过后用它拿结果，不要重复调用变更工具 |
| `approval.resume` | 审批通过后继续执行，平台校验参数一致且只执行一次；用于历史卡单或自动执行失败后重试 |

DSH 驱动任务的链路：

```text
task.create
  → 模型按 SKILL.md 调知识/运维工具
      ├─ 只读：直接执行，事件挂到任务
      └─ 变更：返回 awaiting_approval，任务挂起
  → 人在网页/API 审批
      ├─ 通过：平台自动 resume（DSH/adhoc），任务回到执行中并写 tool.result
      └─ 拒绝：外部 Agent 任务标失败，error=审批被拒绝
  → 模型调用 approval.get 取执行结果（不要重复调用变更工具）
  → task.finish
```

网页/平台模型任务（`origin=web`）由本地 runner 等审批结果后自己续跑；DSH、WorkBuddy 等外部任务（`origin=dsh/api`）和 adhoc 审批没有本地 runner，所以平台在通过后自动执行，避免任务永远停在待审批。审批仍然只消费一次，自动执行失败时可以在审批页点「继续执行」重试。不调用 `task.create` 时，代理会在第一次工具调用时自动建一个 `DSH: <tool>` 任务，避免模型直接调工具后平台没有记录。模型如果忘了调 `task.finish`，代理在 120 秒没有新工具调用后自动把任务标成完成（可用 `AIOPS_IDLE_FINISH_MS` 调整）；网页任务详情里也可以手动「标记完成」。客户端直接断开或进程退出时，内存里的空闲计时器会一起丢，平台每 30 秒按最后活动时间兜底收尾：`origin=dsh/api` 的任务超过 2×`AIOPS_IDLE_FINISH_MS`（默认 240 秒）没有新事件、且没有挂起审批，就标记完成并写「外部 Agent 会话空闲，平台自动结束」。`approval.resume` 对 adhoc 审批同样有效。

本地网页提交任务在未配置模型时走 `playbook.json`，作为没有 DSH 时的降级路径和回归测试；配置模型后由平台 runner 执行。外部 Agent 则通过 `/api/v1` 建 `origin=api` 的任务，自己驱动工具调用。

### 在 DSH 桌面版和 WorkBuddy 里配置（示例）

两边都走账号模式：在「账号 → 用户管理」给客户端建独立账号（角色 `operator`、密码留空、勾选创建时签发 API key），token 只显示一次。不要给 `approver`，外部 Agent 不参与审批。分开建号是为了审计里能区分任务来源。

**DSH 桌面版**：用 `dsh-mcp-manager-plus` 插件时，配置在 `~/.dsh/profiles/<profile>/cordis.patch.yml`（macOS 默认 profile 是 `desktop`），在 `mcp-manager.servers` 下加一条。远程连接用 Streamable HTTP：

```yaml
- id: mcp-manager
  config:
    servers:
      aiops:
        transport: streamable-http
        url: http://<平台地址>:8787/mcp
        headers:
          Authorization: Bearer <dsh 账号的 API key>
        enabled: true
```

平台和 DSH 在同一台机器、想跑本仓库代码的 stdio 代理时，改成：

```yaml
      aiops:
        transport: stdio
        command: <node 可执行文件>
        args:
          - <仓库路径>/node_modules/tsx/dist/cli.mjs
          - <仓库路径>/extensions/mcp/src/main.ts
        cwd: <仓库路径>
        env:
          AIOPS_API: http://<平台地址>:8787
          AIOPS_API_TOKEN: <dsh 账号的 API key>
        enabled: true
```

**WorkBuddy**：配置在 `~/.workbuddy/mcp.json` 的 `mcpServers` 里：

```json
"aiops-harness": {
  "type": "http",
  "url": "http://<平台地址>:8787/mcp",
  "headers": { "Authorization": "Bearer <workbuddy 账号的 API key>" }
}
```

不要用 `AIOPS_INTERNAL_TOKEN` + `AIOPS_ACTOR` 的 header 模式接账号模式的平台，这两个值只在 `AIOPS_AUTH` 未设置的本机模式生效，打过去只会 401。

**验证**

- 客户端工具列表应包含 `task.*`、`approval.*`、`knowledge.*`、`asset.*`、`ssh.*` 和 `mcp.<server>.*`，与平台 `GET /api/tools` 一致。
- 先调只读工具确认链路；变更工具返回 `awaiting_approval`，到网页审批后平台自动执行，客户端用 `approval.get` 取结果，不要重复调用。
- 平台任务列表出现 `origin=dsh` / `origin=api` 的任务，过程事件和审计能正常查看。
- 连不上先探端点：`curl -X POST http://<平台地址>:8787/mcp -H 'content-type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'`，不带 key 返回 401 说明网络和路由正常，再核对 `Authorization` 和 key 的 scope。

### 监控、日志、Kubernetes 到底走不走 MCP

现在全部走上游 MCP：

- 平台 → 真实系统：通过配置的 Streamable HTTP MCP server 调用，工具名 `mcp.<server>.<tool>`。
- DSH → 平台：本机用 `npm run mcp` 的 stdio 代理，远程用平台 `/mcp` 端点，看到同一批工具，任务和审批仍在平台。
- 只读工具直接执行并审计；`risk: mutate` 的工具先产生审批。
- 平台不再保留本地直连的 `prometheus.query`、`es.search`、`k8s.*`，也没有 fixture 兜底工具。

这样审批和审计始终在模型与变更之间。上游 MCP 自己的权限边界仍然在上游（kubeconfig、RBAC、ES 账号），平台的风险标签只是第二道闸。

## 9. 部署和备份

### 9.1 Docker Compose

镜像用多阶段构建：构建阶段 `npm ci && npm run build`，运行阶段只带 `dist/`、生产依赖、`web/`、`config/` 和 `docs/openapi.json`，以 UID 10001 非 root 运行，根文件系统只读，`/tmp` 用 tmpfs。

新环境全程手工配置，不迁移旧数据；逐文件步骤见 `deploy/MANUAL.md`，概览见 `deploy/README.md`：

```sh
docker network create aiops-net   # 已存在会报错，忽略即可

# 1. MCP：每个目录一份独立 compose（MCP 容器 + nginx 认证），复制出去改常量
cp -r deploy/mcp-k8s-read /opt/aiops/mcp-k8s-ro
cd /opt/aiops/mcp-k8s-ro
# 按目录里的 README 改 user、kubeconfig、nginx.conf 的 token
docker compose up -d
cd ../..
# deploy/mcp-vm、deploy/mcp-es 同理，各自目录里有 README

# 2. 平台 + MySQL
cp .env.example .env && chmod 600 .env
# 填 MYSQL_*、AIOPS_DB_*、AIOPS_ADMIN_PASSWORD、AIOPS_UID/GID、AIOPS_PUBLIC_URL
docker compose up -d --build
curl http://127.0.0.1:8787/health
curl http://127.0.0.1:8787/ready
```

MCP 默认不发布宿主机端口，平台通过 `http://mcp-k8s-read-auth:8765/mcp`、`http://mcp-vm-auth:8080/mcp`、`http://mcp-es-auth:8080/mcp` 等服务名访问。K8s MCP 容器用 compose 里的 `user:`（kubeconfig 属主的 UID/GID）运行，kubeconfig 保持 `0600` 也能读。token 直接写在各自目录的 `nginx.conf`，平台「能力 → MCP」添加条目时粘贴同一个值，平台加密落盘，不需要环境变量。

写权限 K8s 集群用 `deploy/mcp-k8s-write/` 模板部署：复制目录、换集群名、token、kubeconfig，一个目录一个集群，不用 `.env` 也不用脚本；平台「能力 → MCP」按 `http://mcp-k8s-<集群>-auth:8766/mcp` 添加条目，`readOnly: true` + 完整 `mutateTools`，读写自动执行、写走审批。每集群必须独立 kubeconfig，且不要用集群管理员。详见 `deploy/mcp-k8s-write/README.md`。

手工部署：

```sh
cp .env.example .env
chmod 600 .env
# 填 MYSQL_*、AIOPS_DB_*、AIOPS_ADMIN_PASSWORD；AIOPS_UID/GID 必填：
# Linux/macOS 用 id -u / id -g 的值，例如 AIOPS_UID=1000、AIOPS_GID=1000
docker network create aiops-net   # compose 使用 external 网络，已存在会报错，忽略即可
docker compose up -d --build aiops
curl http://127.0.0.1:8787/health
curl http://127.0.0.1:8787/ready
```

- compose 默认只绑 `127.0.0.1`（平台 8787，MySQL 3307）；局域网访问要在 `.env` 里设 `AIOPS_BIND_ADDR=0.0.0.0`。内网 HTTP 只适合可信网段，跨不可信网络必须加 TLS 反向代理，不要直接把端口暴露到公网。
- `data/` 是绑定挂载，容器 UID/GID 必须能读写宿主机的 0600 文件；这就是 `AIOPS_UID` / `AIOPS_GID` 的用途。K8s 里由 PVC 和 `fsGroup` 处理，不需要这两个变量。
- compose 默认用 `config/platform.json`，不预置上游 MCP。新部署按 `deploy/MANUAL.md` 4.2 写空的 `data/mcp-servers.json`，登录后在「能力 → MCP」添加，URL 指向 `aiops-net` 里的 `mcp-k8s-read-auth:8765`、`mcp-vm-auth:8080`、`mcp-es-auth:8080` 等。上游 MCP 如果跑在宿主机，容器里的 `127.0.0.1` 指向容器自己，URL 要用 `http://host.docker.internal:<端口>/mcp`（compose 已加 `host.docker.internal:host-gateway`）；生产环境改成 MCP 的 Service 名。
- 首次启动空库时平台自动建表、跑迁移，并用 `AIOPS_ADMIN_USERNAME` / `AIOPS_ADMIN_PASSWORD` 建管理员；登录后立即改密，再把 `AIOPS_ADMIN_PASSWORD` 从 `.env` 移除。
- `data/` 是权威运行数据（资产、凭证、MCP、通知、知识、`secret.key`），`config/` 只在对应 `data/*.json` 不存在时做种子。升级镜像不会覆盖已有数据。
- MySQL 数据在 Docker volume `aiops-harness_aiops-mysql-data`；`data/` 在宿主机目录。两者必须一起备份，只备一个恢复不出完整状态。

### 9.2 备份和恢复

`deploy/backup.sh` 不依赖平台进程，宿主机 cron 和 K8s CronJob 共用：

```sh
BACKUP_PASSPHRASE='...' ./deploy/backup.sh
# 或把口令写进 0600 的 backups/backup.passphrase
```

产物是 `backups/aiops-<时间戳>.tar.gz.enc` 和 `.sha256`，内容包含 `manifest.json`、`mysql.sql`、`data.tar.gz`，用 AES-256-CBC + PBKDF2 加密。默认保留 14 天，周日副本保留 56 天；设置 `BACKUP_RCLONE_REMOTE` 可以再传一份到远端（本机有 rclone 时）。

恢复前先停平台，并先在非生产库演练：

```sh
docker compose stop aiops
BACKUP_PASSPHRASE='...' ./deploy/restore.sh --file backups/aiops-xxx.tar.gz.enc --yes
docker compose start aiops
```

`restore.sh` 支持 `--target-db` 恢复到另一个库；就地恢复会把旧 `data/` 改名为 `data.bak.<时间戳>`，不会直接删除。设置 `RESTORE_MYSQL_MODE=host` 时直接连 `AIOPS_DB_*`，用于 K8s 或外部 MySQL；K8s 的完整恢复步骤和 Job 示例在 `deploy/k8s/README.md` 和 `deploy/k8s/restore-job.example.yaml`。恢复后必须使用同一个 `AIOPS_SECRET_KEY`，否则 `enc:v1:` 的凭证无法解密。备份口令和 `AIOPS_SECRET_KEY` 丢失都无法找回，必须单独保管。

### 9.3 Kubernetes

清单在 `deploy/k8s/`，入口是 `deploy/k8s/README.md`。当前是简化版：平台和 MySQL 各 1 副本，只有平台建 Ingress，MCP 和 MySQL 不对外；不做 NetworkPolicy、不做 mTLS、不加认证代理。平台和上游 MCP 之间靠 header token 认证。

```sh
kubectl --context <ctx> apply -k deploy/ --dry-run=client
kubectl --context <ctx> apply -k deploy/
```

先按 README 创建 `aiops-secrets` 和 `mysql-secrets`，替换所有 `replace-with-*`，并修改 `AIOPS_PUBLIC_URL`、镜像 tag。`aiops-secrets` 里的 `AIOPS_ADMIN_USERNAME` / `AIOPS_ADMIN_PASSWORD` 只在 MySQL 用户表为空时 bootstrap 管理员，首次登录强制改密；已有数据库不会用这个初始密码重置管理员。`AIOPS_INTERNAL_TOKEN` 覆盖 ConfigMap 里空的 `internalToken`。

清单默认按内网 HTTP 部署：Ingress 不绑定 host，IP 或域名都能访问，`AIOPS_COOKIE_SECURE=0`，`AIOPS_PUBLIC_URL` 写 `http://<IP或域名>[:端口]`。Deployment 已设置 `AIOPS_TRUST_PROXY=1`，从 Ingress 追加的 `X-Forwarded-For` 最右侧取客户端 IP；如果集群内 Pod 能绕过 Ingress 直连 Service，需要网络策略或去掉这个开关。Secret 里的 `AIOPS_METRICS_TOKEN` 是必填项，Prometheus 抓取要带同一个 Bearer token。启用 HTTPS 时再恢复 Ingress 的 `tls` 段、创建 `aiops-tls`，把 `AIOPS_COOKIE_SECURE` 改成 `1`、`AIOPS_PUBLIC_URL` 改成 `https://...`。不要同时设置 `AIOPS_TLS_CERT_FILE` / `AIOPS_TLS_KEY_FILE`，否则 K8s 的 HTTP probe 会失败；那种模式要同步改 probe 和 Docker HEALTHCHECK。

镜像 tag 用不可变版本或 digest，不要 `latest`。部署后跑只读检查：

```sh
CONTEXT=<ctx> ./deploy/k8s/preflight.sh
```

清单默认单副本，`RWO` PVC 也不能多挂。

多副本运行需要额外满足这些条件：每个副本设置唯一 `AIOPS_INSTANCE_ID`（建议从 `POD_NAME` 注入）；`/mcp` 会话仍在进程内存，必须让同一 DSH 会话粘在同一副本；任务由创建它的 runner 执行，副本挂掉不会自动迁移，启动回收只标记本实例 `runnerId` 的任务失败。审批结果、账号登录失败锁定、保留期清理已经走 MySQL（审批默认 2 秒轮询，后台清理用 `GET_LOCK` 串行）；HTTP 限流计数仍在进程内。

### 9.4 上游 MCP 认证

平台连上游 MCP 时支持可选 HTTP headers；值里可以引用环境变量，避免把 token 写进 `data/mcp-servers.json`：

```json
{
  "name": "k8s",
  "url": "http://k8s-mcp.mcp.svc:8080/mcp",
  "headers": { "Authorization": "Bearer ${MCP_K8S_TOKEN}" }
}
```

- 不配置 `headers` 就匿名连接，兼容没有认证的 MCP。
- 页面和 `GET /api/mcp-servers` 只返回 header 名，不返回值；编辑时值留空表示保持原值。
- 删除 header 要显式写 `"clearHeaders": ["Authorization"]` 或 `"clearHeaders": true`。
- 环境变量在每次请求时解析；变量缺失会让这次调用失败并报出变量名，不会退回无认证。
- 上游 MCP 必须自己校验 token。平台只能决定“带不带 token”，不能替一个不校验 token 的上游做认证。

## 10. 常见问题

- `401 缺少 X-Actor-Id`：接口没带身份头。浏览器页面会自动带，curl 要手动加。
- `403 当前身份不能提交任务`：用了 `viewer`。
- `403 不能审批自己名下的变更`：换另一个审批人。
- 知识搜不到：本地库检查 frontmatter 的 `actors` 是否包含当前身份；外部库检查 dataset 和过滤逻辑。
- ES 返回 0 条：先确认索引模式和时间窗口，再确认查询字段。只写 `message`、`host`、`ident`、`pri` 这些实际存在的字段；写 `program`、`severity`、`log.level` 不会报错，只会空结果。ES 8 的 API Key 要放 `apiKey`，不是 `token`。
- ES 报 401/403：问题在上游 MCP 的 ES 账号或 headers，平台不保存 ES 凭据。
- ES MCP 工具报 `terminated` 或等待很久才失败：认证代理把平台 token 透传给了 ES MCP，上游会拿它当 ES API key，ES 返回 401。`deploy/mcp-es/nginx.conf` 必须是 `proxy_set_header Authorization "";`，改完重启 `es-auth`。平台现在增量读取 SSE，拿到匹配响应就断开、报错立即返回；还看到 `terminated` 说明上游直接断连，重点查代理和证书。等待超时则报「等待响应超过 `timeoutMs`」，说明上游始终没返回匹配的响应。
- MCP 工具缺失：看「能力 → MCP」的错误提示和健康列；连续失败 3 次会摘工具，恢复后自动注册。
- 任务一直停在等待审批：到「审批」页用另一个审批人处理；审批人不能是任务所有者。DSH/adhoc 审批通过后会自动执行；升级前排队的已通过审批不会自动补跑，可在审批页点「继续执行」。
- 重启后网页/平台模型任务显示「失败：平台重启，任务中断」：任务和审批在 MySQL 里持久化，重启会打断本地 runner；平台启动时会把 `origin=web` 且未结束的任务标记失败，并拒绝挂起的审批。设置了 `AIOPS_INSTANCE_ID` 时只回收本实例 runner 的任务，其它副本的在途任务不动。`origin=dsh/api` 的外部任务不在这里回收，由调用方收尾。
- WorkBuddy/DSH 里对话已经结束，平台任务还显示执行中：外部任务靠客户端发 `task.finish` 结束；客户端关闭 MCP 会话时平台会跟着收尾，客户端直接断开或进程退出则靠兜底扫描，最多约 4 分半（2×`AIOPS_IDLE_FINISH_MS` + 30 秒扫描间隔）后自动标记完成。一直不动说明平台没收到任何结束信号，检查客户端是否还有会话存活、`AIOPS_IDLE_FINISH_MS` 是否被设得很大。有挂起审批的任务不会被兜底收尾，按审批过期处理。
- 审批在另一个副本通过了，执行方没动静：确认 `AIOPS_APPROVAL_POLL_MS` 没被设成 0；执行中的 runner 最迟一个轮询周期后继续。本地同进程审批是立即唤醒的。
- 登录提示 429 但换个副本还能登：先看错误码。账号登录失败锁定在 MySQL，所有副本共享；HTTP 登录限流计数在进程内，换副本可能绕开，需要在前置网关做全局限流。确认是 `locked` 时，管理员去「账号 → 用户管理 → 登录失败与锁定」点「解锁」，或直接重置该用户密码，都会清掉失败记录；不处理则从最近一次失败起 15 分钟后自动解除。
- MCP 连不上：先用 `curl` 打同一个 `url`，确认网络、证书和 headers；平台只连上游 MCP，不再直连 K8s/ES。
- 平台启动即退出，日志是 `AuthError: 密码至少 12 个字符`：`AIOPS_ADMIN_PASSWORD` 太短。改 `.env` 后重建平台容器；失败时用户表为空，改对密码重启会重新 bootstrap，初始管理员首次登录要改密。
- 本机或内网访问 `http://<ip>:8787` 不通：先看 `ss -lntp | grep 8787`，只监听 `127.0.0.1` 就是没开。`.env` 设 `AIOPS_BIND_ADDR='0.0.0.0'` 后 `--force-recreate` 平台容器，改端口映射必须重建。
- MySQL 报 `Access denied for user 'aiops'` 但 `.env` 密码改过：MySQL 的 `MYSQL_PASSWORD` 只在数据卷首次初始化时生效，已有 volume 不会跟着改。用 `MYSQL_PASSWORD` 实测能连就说明是 `.env` 里 `AIOPS_DB_PASSWORD` 不一致，改它并重建平台容器。
- 构建时 `npm ci` 大量 `ETIMEDOUT` 或 `npm error Exit handler never called!`：构建容器没有出网，不是 npm bug。`iptables: false` 的节点需要补 MASQUERADE，或临时用 `docker build --network=host`；详见 `deploy/MANUAL.md` 常见问题。

## 12. 当前不支持清单

- 没有本地直连工具；Prometheus、K8s、Loki、ES 的能力完全取决于上游 MCP 暴露了哪些工具。
- 没有内置写权限模型：真实变更需要单独接入可写 MCP，并用最小权限账号限制。
- 没有配置模型时，网页 playbook 只做知识检索；配置模型后平台做有限步排查，但复杂会话和编排仍在 DSH / WorkBuddy。
- 多实例已经支持共享审批结果、账号登录失败锁定和清理锁，但 HTTP 限流计数仍在进程内；任务执行不迁移：实例挂了，它的 runner 任务只能等该实例重启或由管理员收尾；`/mcp` 会话仍需粘性。K8s 清单默认仍是单副本。
- 任务/审批列表已下推 MySQL 分页；`GET /api/security-events` 的 `total` 来自单独计数，数据量极大时会有轻微不一致。
- 审批跨实例有最多 `AIOPS_APPROVAL_POLL_MS`（默认 2 秒）的延迟；后台清理用 `GET_LOCK` 串行，拿不到锁的副本直接跳过本轮。
- 强制改密只拦截网页会话，API key 不受影响（客户端账号设计如此）；管理员重置密码会立即吊销该用户全部网页会话并标记必须改密。用户自己改密成功时只吊销其它会话，当前会话保留。
- API key 到期提醒只在进程内去重，且依赖已配置的通知渠道；多个副本滚动重启可能重复提醒一次。
- SSH 已做 host key 校验（TOFU + 管理员确认），支持 known_hosts 导入和多层跳板机（direct-tcpip）；不支持 SFTP、交互式 TTY、SOCKS/动态代理转发；`ssh.exec` 是非交互执行，需要 TTY 的命令会失败。`ssh.read` 只覆盖白名单命令，`ssh.logs` 只读资产声明的路径，两者都不接受自由 shell；`ssh.logs` 的 `grep` 是固定字符串匹配，不支持正则。
- SSH 密码和私钥（凭证或资产内联）已加密落盘；密钥文件 `data/secret.key` 与数据同机，主机被攻陷时仍可能同时拿到。
- 上游 MCP 只支持 Streamable HTTP；stdio 形式的上游 MCP 还没接。
- 平台 MCP 服务端只有 stdio 和 Streamable HTTP 两种，没有 SSE 推送；远程会话状态在单实例内存里，多实例需要粘性会话。
- 多租户、OIDC/SAML/统一身份源直连（当前只有本地账号）。
- HTTP 限流计数在进程内存，多实例部署时每个实例独立计数；账号登录失败锁定在 MySQL，多实例共享。
- Docker Compose 和 K8s 清单都按单副本设计；K8s 没有 NetworkPolicy、mTLS 和 MCP 认证代理，MCP/MySQL 的 ClusterIP 在集群内可达，靠上游 token 和数据库密码保护。
- K8s 默认内网 HTTP，不做传输加密；跨网段或不可信网络应启用 Ingress TLS。
- 备份是逻辑备份，不是时间点恢复；恢复会停平台，RPO 取决于备份频率。
- 强制改密会拦截网页会话的其它接口（403 `password_change_required`），只放行 `/api/auth/me`、改密和登出；API key 不受影响。管理员重置密码后该用户的网页会话立即失效，需要重新登录并改密。
